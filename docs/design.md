# 小学生零花钱记账 Web 应用 - 基础设计文档（MVP）

## 1. 产品定位

- **目标用户**：小学阶段孩子（主要操作）+ 家长（共同制定规则）
- **核心目标**：帮助孩子形成“先计划、再消费、会复盘”的习惯
- **边界**：纯网页端，不依赖后端服务

## 2. 功能范围

### 2.1 零花钱共识契约
- 契约字段：
  - 每月金额
  - 发放方式（一次/分次）
  - 推荐储蓄比例
  - 可消费范围
  - 需和家长商量的消费金额阈值
- 支持版本记录（每次修改保留时间戳）

### 2.2 月度使用计划
- 计划分类（默认）：
  - 自己使用
  - 送礼
  - 储蓄
  - 其他
- 支持百分比与金额双视图

### 2.3 月度实际流入流出
- 流入：零花钱发放、奖励等
- 流出：消费支出
- 每条记录字段：
  - 日期
  - 金额
  - 分类
  - 备注

### 2.4 汇总页面
- 月度总收入 / 总支出 / 结余
- 计划 vs 实际对比
- 储蓄进度
- 简单复盘提示（可由 AI 生成）

### 2.5 AI 对话助手
- 场景：
  - “我这个月还可以花多少钱？”
  - “我最近花钱有什么特点？”
  - “我想买 XXX，合理吗？”
- AI 输出应偏教育引导，不进行风险或医疗等专业建议

## 3. 信息架构（页面）

1. 首页 / 仪表盘
2. 共识契约
3. 月度计划
4. 收支记录
5. 汇总分析
6. AI 助手
7. 设置（主题、数据导入导出、AI Key）

## 4. 数据设计（本地）

建议使用 IndexedDB（可配合 Dexie）：

- `contracts`
  - `id`, `createdAt`, `monthlyAllowance`, `savingRatio`, `rules`, `threshold`
- `monthlyPlans`
  - `id`, `month`, `items[]`（分类、计划金额、计划比例）
- `transactions`
  - `id`, `date`, `month`, `type(income|expense)`, `category`, `amount`, `note`
- `appSettings`
  - `theme`, `aiProvider`, `aiModel`, `apiKeyMaskedHint`

## 5. 技术方案

- **前端框架**：React + TypeScript（可由 Vite 初始化）
- **状态管理**：优先轻量方案（React Context + hooks）
- **本地存储**：IndexedDB
- **样式**：CSS Variables + 主题 token
- **图表**：轻量图表库（可选）
- **导入导出**：JSON（版本号字段确保兼容）

## 6. 主题设计

至少提供 3 套主题：

1. 可爱风（柔和色、圆角、贴纸感）
2. 帅气风（高对比、深色、科技感）
3. 简约风（中性色、低干扰）

统一通过 Design Tokens 驱动，避免每页单独写样式分支。

## 7. AI 接入策略（纯前端）

- 用户在设置页输入 API Key，本地保存（可选 session 级别）
- 所有请求直接由浏览器发出
- 统一封装 `aiClient`，屏蔽不同供应商细节
- 提供：
  - Key 删除
  - AI 功能开关
  - 基础错误处理（限流、超时、无网络）

> 注意：纯前端保存密钥存在泄露风险，MVP 可接受；若后续上线公开使用，建议迁移到后端代理。

## 8. 导入导出设计

- 导出：下载 `mao-ledger-backup-YYYY-MM.json`
- 导入：文件校验（JSON 格式、版本号、字段完整性）
- 处理策略：
  - 覆盖导入
  - 合并导入（按 `id` 去重）

## 9. 非功能要求

- 儿童友好：文案简短、按钮大、反馈明确
- 可访问性：对比度、字号、键盘可达
- 隐私：默认仅本地存储，不上传数据

## 10. 里程碑建议

1. M1：完成本地数据模型 + 四大核心页面
2. M2：完成主题切换 + 导入导出
3. M3：接入 AI 对话 + 复盘建议模板
